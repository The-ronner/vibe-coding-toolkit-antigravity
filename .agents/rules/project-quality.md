# Project quality rules

Keep the repository documentation-first. Do not add an application, root runtime dependencies, hidden network calls, credentials, Git blockers, or automatic hooks. Preserve existing client integrations while adding portable Antigravity support.

Before editing, inspect the relevant source, templates, callers, and validation. Make the smallest complete change, preserve local customizations, and run the checks that cover the changed contract. Never claim a tool, skill, MCP server, authentication flow, or host interaction was tested unless it was actually observed.

Use current official documentation for Antigravity behavior. Keep `AGENTS.md` short and client-neutral; put multi-step procedures in skills and detailed knowledge in `docs/`. Update indexes, links, examples, and validators together when a public path changes. Never place secrets in repository files or queries.
